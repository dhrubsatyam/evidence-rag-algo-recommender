## Results

### Model learning / training behavior

- **Neural family tagger (from scratch)**: 571 train / 100 val records,
  40 epochs, ~4.5 s on Apple MPS. Training log
  (`outputs/neural/train_log.jsonl`) shows classic overfitting: train
  loss falls 1.07 → 0.23 while validation loss bottoms near epoch ~27
  (≈0.97) and then rises to 1.23. Best-validation checkpoint
  (macro-F1 = **0.477**) is kept — evidence the model *did* learn
  mention patterns but is capacity/data-limited, not underfit.
- **Underfit vs overfit**: early epochs show both losses decreasing
  together (learning); after ~epoch 28 divergence = overfitting on
  weak labels. Mitigations already in place: dropout 0.3, weight
  decay 1e-4, early-stopping checkpoint.
- **Generator (Qwen2.5-0.5B-Instruct)**: not trained by us; fixed
  greedy decoding, ~3.3 s mean latency per answer on MPS.

### Evidence for the hypothesis (retrieval improves grounding)

Hypothesis: grounding generation in retrieved abstracts improves
citation quality and reduces unsupported claims vs. the same model
without retrieval.

- With retrieval: **10/10 dev cases** produced resolved citations
  (extractive) and **9/10** (local_lm); without retrieval every case is
  explicitly marked `ungrounded_baseline` and cites nothing — the
  system never fabricates IDs in the no-retrieval arm.
- **Unsupported citation IDs: 0** across all 40 generation rows
  (both generators). Citation-resolution check strips anything not in
  the retrieved set.
- Ablation (`outputs/ablation.json`, dev cases, extractive):

  | Retrieval variant | status ok | cited IDs | unsupported | low-evidence cases |
  | --- | --- | --- | --- | --- |
  | BM25 only | 10/10 | 18 | 0 | 0 |
  | Dense only | 9/10 | 11 | 0 | 0 |
  | BM25 + dense (RRF) | 9/10 | 18 | 0 | 0 |
  | BM25 + dense + neural | **10/10** | **27** | 0 | 0 |

  → The from-scratch neural tagger as a third RRF signal raised total
  resolved citations ~50% (18 → 27) and recovered the one case dense
  retrieval alone missed. Dense-only was weakest — lexical matching
  carries most of the signal on this corpus.
- Probes: out-of-scope → `insufficient_evidence`; missing constraints →
  clarifying questions; citation probe resolves — all pass.

### Effect on the application (user experience)

- End-to-end request latency: ~3–5 s with local_lm on MPS; ~0.1 s
  extractive. No crashes observed across dev cases + probes.
- Edge cases handled by design: blank constraint → clarification
  questions (not a guess); non-tabular task → explicit
  insufficient-evidence refusal; low retrieval similarity →
  `low_evidence` flag prefers abstention.
- Remaining UX limits: 240-token cap truncates long answers; the UI is
  a single local page (no auth/multi-user); held-out human scoring
  still pending.

## Conclusion

- **Goal**: evidence-grounded algorithm recommendation for tabular
  classification — retrieve ML abstracts, return a cited shortlist
  with trade-offs and uncertainty, compare the same local model ±
  retrieval.
- **Outcome vs goal**: met for the prototype scope — every dev-case
  answer is either cited-and-grounded or explicitly marked
  ungrounded/insufficient; zero fabricated citations in 40 rows.
- **Most significant result**: hybrid retrieval works — and adding the
  self-trained neural family tagger as a third RRF signal was the
  single biggest citation-yield improvement in the ablation (18 → 27
  cited IDs), suggesting family-aware signals complement lexical and
  semantic matching.
- **Unexpected result**: dense retrieval alone underperformed BM25 on
  this abstract corpus — exact term matching (algorithm names,
  dataset terms) mattered more than embedding similarity at top-k=5.
- **Next steps**:
  1. Run the sealed 20 held-out cases and collect human 0–2 rubric
     scores (retrieval relevance, suitability, evidence support).
  2. Extend the ablation to `local_lm` generation and add
     recall-oriented retrieval metrics once relevance labels exist.
  3. Improve the tagger: better labels (LLM-assisted or human-
     verified family annotations), larger corpus, possibly sequence
     model (CNN/biLSTM) or TF-IDF+MLP comparison.
  4. Productionization path: batch/precompute family scores on corpus
     update, add retrieval caching, containerize (`Dockerfile`),
     optional hosted embedding endpoint, and a feedback loop where
     user corrections become new weak labels.
